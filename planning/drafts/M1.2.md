## Outcome

Every adapter probe has a real private KWin session and deterministic custom-rendered application available before production implementation.

## Milestone

#1

## Dependencies

#9

## Scope

- Add a development harness using a transient user service, private bus/runtime/HOME/XDG and headless KWin with one 1280×720 scale-1 output; keep all ordinary children in its cgroup.
- Add a minimal native Wayland fixture with custom rendering, machine-readable input acknowledgments and controllable visual state; provide a separate local test control channel to request state changes.
- Bound startup and teardown, preserve generation-attributed evidence outside disposable settings, and prevent any host input/capture fallback.

## Acceptance criteria

- [ ] The harness opens the fixture on the private desktop without prompts; its reported output configuration is correct and it requires no viewer or accessibility metadata.
- [ ] The fixture emits deterministic input receipts and signals when an intended visual change has been rendered; later screenshot checks can synchronize using that signal.
- [ ] Normal completion and injected startup failure remove owned processes within a recorded provisional deadline and retain diagnostics. This harness is clearly marked as feasibility tooling, not a supported session implementation.
