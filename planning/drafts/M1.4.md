## Outcome

Project-owned libei calls can negotiate usable devices, deliver acknowledged input and observe connection/device failures in the private compositor.

## Milestone

#1

## Dependencies

#10

## Scope

- Declare only required ctypes symbols, verify argument/return types and object/FD ownership against installed supported headers, including void ei_dispatch.
- Demonstrate GLib-integrated event consumption, resumed-device gating, key press/release and cancellation with acknowledgment from the M1 fixture.
- Establish a reproducible real-compositor lifecycle fault procedure for pause/removal/disconnect and reset; document any required harness extension. Record binding maintainability and known correctness issues.

## Acceptance criteria

- [ ] Header audit and real input evidence pass; no input is emitted on merely announced or paused devices and released keys are observed by the fixture.
- [ ] A concrete fault-injection/reproduction procedure and evidence exist for lifecycle events; inability to obtain required evidence remains a blocker, not a mock-only pass.
- [ ] Record measured initial cancellation/release behavior and a justified Python-versus-compiled-boundary decision; unresolved input correctness defects block the milestone.
