## Outcome

A reproducible, bounded compatibility harness proves the proposed platform adapters on the target Arch Linux/KDE Wayland machine before their interfaces are committed to production.

## Dependencies

None.

## Scope

- Record target package/native-library versions, exact source revisions, resolved Python environment, maintained patches, and setup steps; evaluate the proposed kdotool revision.
- Run an owner-private bus and headless KWin at 1280×720 scale 1 inside a transient user service with bounded cleanup and durable diagnostic output.
- Build a minimal deterministic native Wayland custom-rendered fixture with input acknowledgments and controllable visual state for the initial window/input/capture probes; this fixture is reusable by production adapter tests.
- Probe structured custom-rendered window queries and verified focus using kdotool, resumed EIS/libei devices and acknowledged input using project-owned bindings, and fresh ScreenShot2 capture with concurrent pipe draining.
- Record measurements and choose finite proposed startup, query, action, cancellation, capture and shutdown limits; record blockers and evidence-based design changes.

## Acceptance criteria

- [ ] A checked-in harness and evidence demonstrate all three adapters in the intended private service environment without prompts or touching the host desktop.
- [ ] The limited ctypes surface is checked against supported libei headers, including void ei_dispatch and event/object ownership; input correctness defects are resolved before that adapter passes.
- [ ] Setup is reproducible from recorded versions and any patches; missing capabilities produce actionable failures. Each failed probe cleans up its owned processes within a recorded bound.
- [ ] An architecture decision records go/no-go for kdotool, Python/libei, capture isolation and the GLib loop. A blocker prevents dependent production integration until resolved; prototype results are explicitly not a support claim.
