## Outcome

The Python CLI and persistent-worker contract provide predictable machine-readable results, identity checks, caller-relative paths, finite deadlines and durable diagnostics.

## Dependencies

#1

## Scope

- Package agent-desktop with explicit flags/defaults and all documented command families; commands not yet wired fail explicitly rather than reporting success.
- Define a versioned owner-only Unix-socket JSON protocol with request IDs, generation-scoped handles, structured errors and meaningful exit status, including parser failures.
- Implement request admission, monotonic deadlines including queue time, single ordinary-action serialization and responsive cancellation/reset/stop control handling.
- Define generation-specific durable artifacts, atomic manifests, correlated logs, caller path normalization, executable/PATH and environment precedence; record headless mode.

## Acceptance criteria

- [ ] Separate CLI processes exchange requests with a persistent worker; JSON stdout contains one result only, including errors, and subprocess/application logs stay separate.
- [ ] Every session-addressed command accepts an expected generation and checks it before side effects; name-only resolution and non-retry semantics are documented.
- [ ] Queue delay consumes the timeout; SIGINT and socket loss reach active work without queueing, while required cleanup survives client exit. Test task doubles can establish this infrastructure before real adapters arrive.
- [ ] Artifact paths are caller-relative, generation-specific and collision-free; manifests retain required provenance and outcomes without dumping secrets. Failures identify partial/uncertain effects and retain available application handles.
