## Outcome

Session names resolve to distinct service generations that cannot be confused across start/stop races.

## Milestone

#3

## Dependencies

#1, #2

## Scope

- Serialize per-name start/stop decisions, bind service and runtime paths to random immutable generations and compare all supported configuration for duplicate starts.
- Launch the persistent worker in a transient user service with no automatic restart, KillMode=control-group and finite TimeoutStopSec; retain service identity for fallback stop.
- Guard manager-side start/status/stop and runtime removal with expected-generation checks, including when the worker socket is unavailable.

## Acceptance criteria

- [ ] Repeated compatible start returns the same identity, conflicting start fails, stopped stop succeeds and restarting the same name produces a new generation.
- [ ] Concurrent lifecycle/race checks show stale start/stop requests cannot stop or remove a replacement generation, including the unresponsive-worker path.
- [ ] Separate CLI invocations retain a live session; systemd owns ordinary descendants and records use the correct generation.
