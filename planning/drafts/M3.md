## Outcome

A generation-bound systemd service owns the worker, private desktop and ordinary descendants, with reliable failure detection and an independent cleanup path.

## Dependencies

#1, #2

## Scope

- Implement per-name lifecycle locking, generation-specific unit/runtime ownership, duplicate-start compatibility and idempotent stop.
- Create owner-only runtime and disposable HOME/XDG settings; construct explicit private Wayland/D-Bus endpoints and reject protected overrides, stripping host display and accessibility endpoints.
- Supervise private bus and KWin; use no automatic restart, KillMode=control-group, finite TimeoutStopSec and a bounded terminal-record/runtime cleanup hook.
- Implement capability-based readiness using the M1 probe interfaces until production adapters are connected, live status and independent worker/compositor/bus failure detection.
- Provide graceful-shutdown hooks for action cancellation, release and application close, followed by bounded service-manager fallback even with an unresponsive worker.

## Acceptance criteria

- [ ] Sessions survive separate CLI invocations and only become ready after control, window, resumed input and screenshot probes all pass; failed startup retains diagnostics and cleans up.
- [ ] Duplicate starts return the compatible generation or reject conflict. Stale-generation commands, including fallback stop and cleanup hooks, cannot affect a replacement session.
- [ ] Independent death or unresponsiveness tests cover worker, compositor and bus; status rejects work after essential failure and cgroup cleanup removes ordinary descendants within the deadline.
- [ ] Private socket/files have owner-only access; trusted applications keep project/network access while receiving only intended desktop/settings endpoints. Durable artifacts and failure outcomes survive cleanup.
