## Outcome

Targeting and waits use current compositor state and return distinct, actionable outcomes.

## Milestone

#4

## Dependencies

#23

## Scope

- Resolve explicit identity or a unique owned-application association; return candidates on ambiguity, reject vanished/stale-generation references and recheck at execution after queue delay.
- Implement focus as activation followed by bounded observation of the exact active window; provide reusable existence/focus/current-geometry checks for input.
- Add bounded window/focus/app-exit waits that distinguish timeout, application exit, cancellation and failed session and retain launch handles on window timeout.

## Acceptance criteria

- [ ] Identical-title dialogs force explicit selection; windows that vanish or move while queued are revalidated before side effects.
- [ ] Activation subprocess success without observed focus fails or times out; waits cover each documented outcome against the real fixture.
- [ ] Focus queries honor the chosen deadline and return fresh client geometry suitable for click translation; no title-based identity fallback occurs.
