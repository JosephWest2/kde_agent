## Outcome

One native Wayland application and its dialogs can be launched, discovered, focused, waited on, closed or explicitly terminated with generation and process-ownership checks.

## Dependencies

#2, #3

## Scope

- Launch argv without an implicit shell, using normalized cwd and documented final PATH/env; retain application/process identity, logs, descendants and exit state even after timeout or cancellation.
- Implement an asynchronously observed pinned kdotool adapter and fixed safely parameterized query for KWin identity, PID, title/class, client/frame geometry and focus.
- Select by explicit window identity or unambiguous owned-application association; expose candidates and null/unavailable metadata; validate again after queue delay.
- Implement bounded focus/window/exit waits, graceful selected-window close without automatic dialog handling or signaling, and separate owned-process termination.
- Extend the M1 fixture with dialogs, duplicate titles, delayed window creation, exits and descendants while implementing application/window behavior.

## Acceptance criteria

- [ ] Real custom-rendered fixture windows and dialogs are discovered without accessibility; identical titles never substitute for identity and ambiguous or vanished targets fail clearly.
- [ ] Focus succeeds only after the requested window is observed active; waits distinguish exit, timeout, cancellation and session failure.
- [ ] Timed-out window waits retain application handles. PID-reuse simulation and real descendant tests show termination signals only verified owned processes and reports remaining processes.
- [ ] Relative executable/cwd/output paths work from a different caller directory; confirmation dialogs remain available for explicit interaction, and close timeout sends no termination signal.
