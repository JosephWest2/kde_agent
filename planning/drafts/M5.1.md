## Outcome

One worker execution context owns a header-checked private EIS/libei connection and continuously updated device readiness.

## Milestone

#5

## Dependencies

#1, #2, #3, #24

## Scope

- Promote the M1 binding to a limited production module with verified ctypes signatures, explicit object/FD ownership and GLib event integration.
- Negotiate EIS only through the private compositor, consume events continuously and gate emission on usable resumed devices.
- On pause/removal/disconnect mark affected devices unusable, notify the active action to cancel and record release uncertainty; expose readiness/reconnect hooks for reset and startup.

## Acceptance criteria

- [ ] Real event traces demonstrate negotiation and resumed readiness before input; events continue to be consumed during ordinary actions and slow external work.
- [ ] The M1 real-compositor fault procedure exercises pause/removal/connection loss with explicit unavailable errors and resource cleanup; no stale-ready or host fallback path exists.
- [ ] Native declarations/ownership are checked against the recorded headers and no known correctness defect remains; tests supplement but do not replace real lifecycle evidence.
