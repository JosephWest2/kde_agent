## Outcome

Supported input requests compile into finite press/release sequences before any emission.

## Milestone

#5

## Dependencies

#27

## Scope

- Document physical-key names including common game keys, legal chord structure, finite hold limits and the supported US-layout character set.
- Prevalidate the complete request and generate short sequence steps; track explicit keys/buttons and modifiers generated for text, with a release ledger shared by completion/cancellation/reset.
- Extend fixture acknowledgments for key order, modifier state, text and hold duration; expose dispatch results without claiming application rendering.

## Acceptance criteria

- [ ] Supported text/chords/game keys and finite holds are received by the real fixture in the expected order and all normal-completion releases are observed.
- [ ] Unsupported characters anywhere in text, invalid chord keys or invalid/nonfinite holds reject the entire request before emitting any input.
- [ ] No public operation can leave an indefinite key-down state across commands; the ledger includes generated modifiers and identifies uncertain effects.
