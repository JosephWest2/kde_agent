## Outcome

Input executes only after current target checks, with finite rechecks during repeated or held input and correctly translated clicks.

## Milestone

#5

## Dependencies

#28, #24

## Scope

- Require explicit or unambiguously resolved window identity for key/type/click, confirm existence and verified focus before emission and revalidate after queue delay.
- Schedule bounded focus/existence polls during sequences/holds using asynchronous queries; stop further input on lost target/focus or a timed-out check.
- Prevalidate click button/coordinates, then check current client-content bounds and translate to output coordinates excluding decorations immediately before dispatch.

## Acceptance criteria

- [ ] Real fixture clicks at valid client edges reach the expected content positions; negative/out-of-range coordinates fail without emission and moving/resizing queued targets uses new geometry.
- [ ] Focus theft and vanished windows cancel held/repeated input within the measured polling bound; a slow or timed-out query never permits continued input using stale focus.
- [ ] All input commands reject missing/ambiguous/stale targets, and documentation states checked focus-based behavior and its non-atomic compositor race limit.
