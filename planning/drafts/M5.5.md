## Outcome

Explicit reset recovers a usable private input connection or leaves input unavailable with truthful diagnostics.

## Milestone

#5

## Dependencies

#30

## Scope

- Make reset bypass the action queue, ask the input owner to cancel active input first, then release tracked state or replace the private connection.
- Wait for newly usable resumed devices before reporting reset success; clean up old connection resources and never replay interrupted input.
- Provide production release/reset hooks for M7.1 startup/shutdown integration and exercise the established real lifecycle failure procedures.

## Acceptance criteria

- [ ] Reset during a held key cancels the active sequence and restores usable input only after safe release/reconnection; a subsequent targeted action is acknowledged correctly.
- [ ] Connection loss with uncertain release blocks new input until successful reset or session stop, and a failed reset leaves it blocked.
- [ ] Pause/removal/disconnect and repeated reset attempts do not leak connection resources or publish readiness early; reset/stop remain responsive during active input.
