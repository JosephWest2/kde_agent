## Outcome

Keyboard and pointer actions use verified window focus, finite sequences, tracked releases and an event-responsive private libei connection.

## Dependencies

#1, #2, #3, #4

## Scope

- Implement the minimal header-verified ctypes/libei binding and one GLib execution context for device events and emission; require usable resumed devices and process pause/removal/disconnect continuously.
- Prevalidate physical keys, finite holds, complete chords and the documented US-layout text set before input; track generated modifiers as well as explicit keys/buttons.
- Require a window for every input action, recheck current existence/focus/geometry and translate bounded client coordinates excluding decorations.
- Run cancellable short steps with bounded focus rechecks; cancel on target/focus/device loss, SIGINT, disconnect or deadline, including delayed desktop queries.
- Attempt release on all outcomes; expose uncertainty and block further input until successful reset or stop. Reset cancels active work and restores a usable connection without replay.
- Extend the existing fixture and harness with focus theft, modified-text/hold acknowledgments and controlled input-device fault scenarios as each behavior is implemented.

## Acceptance criteria

- [ ] The real instrumented app acknowledges supported text, chords, common game keys, finite holds/releases and content-coordinate clicks; unsupported full requests emit no input.
- [ ] Focus theft, vanished targets, slow/timed-out focus queries, queued actions, modified typing and held input satisfy measured polling/cancellation/release bounds.
- [ ] Device pause, removal and connection loss stop emission, report readiness/uncertainty accurately and require a successful reset where release is uncertain; reset failure leaves input unavailable.
- [ ] Cancellation/reset/stop bypass the ordinary queue and never concurrently manipulate libei. Results explicitly describe dispatch, without implying application acknowledgment or frame readiness.
