## Outcome

Each successful screenshot identifies a newly captured fully written PNG and its generation/provenance.

## Milestone

#6

## Dependencies

#32, #17

## Scope

- Wire screenshot CLI to fresh capture, a unique temporary output, Pillow PNG encoding and atomic complete-file publication; define safe behavior for an already-existing explicit destination.
- Resolve destinations at the calling CLI and return absolute path, dimensions, capture timestamp, backend and generation only after writing completes.
- Keep failed temporary images distinguishable from completed artifacts and preserve earlier screenshots across stop/failure.

## Acceptance criteria

- [ ] Repeated requests yield distinct fresh complete 1280×720 PNGs; fixture-acknowledged visual changes appear and no previous image is returned as a new capture.
- [ ] Disk/write failure, cancellation and partial capture cannot publish a partial PNG as success or destroy an earlier artifact; output paths work from a different caller cwd.
- [ ] JSON stdout is clean and results/documentation make no claim that prior input has been acknowledged or rendered without an application-specific signal.
