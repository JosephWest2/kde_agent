## Outcome

Users can locate generation-attributed diagnostics and understand failed runs after the session runtime has been removed.

## Milestone

#6

## Dependencies

#33

## Scope

- Wire the logs command and artifact index to generation-specific durable storage, with a documented way to inspect stopped/failed-generation artifacts and generation checks on session-addressed requests.
- Connect helper/compositor/bus/capture producers to the M2 manifest/logging API and integrate app records when M4 is available; M7.1 verifies the final complete schema.
- Correlate request IDs, application/window handles and screenshot paths; retain dependency revisions/patches, argv/cwd, mode/geometry, final outcome and cleanup diagnostics without credentials.

## Acceptance criteria

- [ ] Logs/artifacts for stopped and failed startup sessions remain discoverable and cannot be confused with a same-name replacement generation.
- [ ] Manifest completeness checks verify each required field's producer, preserve prior failure outcomes and validate collision-free artifacts; application fields are exercised with M4 records in M7.1.
- [ ] Inspecting artifacts cannot alter session state or pollute JSON output with application logs; screenshots and logs survive runtime/settings deletion.
