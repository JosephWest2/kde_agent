## Outcome

The CLI captures the whole private output as a newly written PNG while cancellation and health monitoring remain responsive, and exposes durable correlated artifacts.

## Dependencies

#1, #2, #3

## Scope

- Implement the direct private ScreenShot2 D-Bus adapter with concurrent pipe drain, validated metadata/pixel format, finite deadlines and owned descriptor/subprocess cleanup.
- Keep blocking capture work outside the control loop using the boundary validated in M1; encode with Pillow, write a unique temporary artifact and publish only a complete PNG.
- Return generation, absolute path, dimensions, capture timestamp and backend; wire logs/artifact discovery and complete manifests for requests, launches, dependency provenance and terminal outcomes.

## Acceptance criteria

- [ ] Real capture without a viewer yields a fresh complete 1280×720 PNG per request; after fixture acknowledgment a changed rendering is visible and prior images are never reused as fresh output.
- [ ] Slow/hung capture, partial reads, unsupported formats, write failures, cancellation and private-bus loss fail with stable context, leak no owned resources and cannot publish partial files as successes.
- [ ] Capture cannot block cancellation, stop or health processing; screenshots/logs/manifest survive failed startup and cleanup, concurrent filename allocation does not collide, and JSON stdout remains clean.
