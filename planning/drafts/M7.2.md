## Outcome

A repeatable automated workflow verifies input and visible results against the real private KWin desktop through separate CLI processes.

## Milestone

#7

## Dependencies

#35

## Scope

- Assemble the existing M1/M4/M5 fixtures and harness with one CLI process per action: doctor/start, launch, discover, focus, capture, type, chord/hold/release, click, close and stop.
- Wait on fixture input acknowledgments and rendered-state signals before expected pixel checks; assert complete PNG metadata and retained application logs/handles.
- Include graceful-close confirmation, explicit termination and window/focus/exit waits, caller-relative path cases and output isolation in the reusable suite.

## Acceptance criteria

- [ ] The full workflow passes on the recorded real target environment and proves expected input receipts plus visual change; mocks alone cannot satisfy it.
- [ ] Every run records environment, generations, requests and artifacts and checks no owned processes or held input remain at teardown.
- [ ] A required unavailable platform capability is a failed qualification prerequisite, not a silent skip; the harness is reusable for the twenty-run gate.
