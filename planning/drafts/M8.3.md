## Outcome

Published support claims match recorded application evidence and every required behavior has an implementation/test reference.

## Milestone

#8

## Dependencies

#40

## Scope

- Select a representative native Wayland app/game relevant to the user's workflow at implementation time; record a successful supported workflow and exact app/environment versions, or document a reasoned REQ-044 exception and consequences.
- Publish a requirement-to-code/test/evidence index for every MUST and disposition for each SHOULD, including reuse choices, diagnostics, configuration and future-viewing compatibility.
- Review the twenty-run report and docs, record remaining environment limitations and explicitly defer REQ-047–050 and all outside-first-version features.

## Acceptance criteria

- [ ] Every REQ-001–040 has passing implementation/validation evidence; every REQ-041–046 is satisfied or has an explicit reason and consequences for an exception.
- [ ] Support is claimed only for recorded successful native app/environment combinations; an optional representative-app exception cannot waive any MUST or the twenty-run gate.
- [ ] No live-viewer, XWayland, richer input/output/multiple-app, MCP, sandbox or general game support commitment slips into the initial release; relevant post-qualification changes trigger revalidation.
